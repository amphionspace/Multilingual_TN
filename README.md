# ICU TTS Text Normalization / ICU TTS 文本归一化

## English

This project is a config-driven multilingual text normalization prototype for TTS frontends. Rules are stored as **JSON** under `rules/`, so most product-side pattern, replacement, unit, and currency tweaks do not require editing C++.

**Phase B - pattern_defs:** each locale file may include a top-level **`pattern_defs`** map of named ICU fragments. **`rules[].pattern`** strings may embed **`{{NAME}}`** placeholders; `TtsNormalizerEngine::loadRules` resolves them after stabilizing mutual references among defs. The syntax matches the generator in `tools/pattern_blocks.py`. Literal TSV rows usually keep plain patterns without placeholders.

### Layout

| Path | Role |
|------|------|
| `en.cpp` / `zh.cpp` / `ar.cpp` / `bn.cpp` / `ru.cpp` | Thin drivers: ICU `RuleBasedNumberFormat` + load JSON + run pipeline |
| `tts_normalizer_engine.hpp` / `tts_normalizer_engine.cpp` | ICU regex runner; pipeline actions are mostly `action: "exec"` with JSON `steps`. Only pinyin and emoji remain as dedicated C++ actions. |
| `rules/en.json` | English pipeline and literal rules |
| `rules/zh.json` | Chinese pipeline and literal rules |
| `rules/ar.json` | Arabic pipeline and literal rules |
| `rules/bn.json` | Bengali pipeline and literal rules |
| `rules/ru.json` | Russian pipeline and literal rules, including morph-aware numerals |
| `rules/zh_pinyin.json` | Tone-marked pinyin to Chinese character mapping |
| `tools/generate_tts_rules_json.py` | Regenerates locale JSON rules from structured Python data |
| `docs/tts_ops.md` | Handoff document for every `exec` step `op` and dedicated action |
| `docs/tts_locale_field_matrix.md` / `.csv` | Reference-only locale field matrix, regenerated by `tools/export_locale_field_matrix.py` |
| `docs/rule.schema.json` | Shared JSON Schema for all `rules/<locale>.json` files |
| `third_party/nlohmann/json.hpp` | Single-header JSON parser, MIT license |

### Editing Rules

1. **Simple find/replace:** add rows to `EN_LITERALS_TSV` / `ZH_LITERALS_TSV` / `_AR_LITERAL_ROWS` / `_BN_LITERAL_ROWS` / `_RU_LITERAL_ROWS` in `tools/generate_tts_rules_json.py`, or extend the `*_pipeline_rules()` lists for new actions.
2. **Units and currency:** edit the `*_unit_*()` and `*_currency_map()` dictionaries in the same script.
3. **New behavior:** prefer adding `exec` steps in `tools/generate_tts_rules_json.py`, or hand-editing `rules/*.json`. Add C++ only when a new primitive is needed inside `applyExecStep`.

Regenerate JSON:

```bash
cd ICU
python3 tools/generate_tts_rules_json.py
```

Validate rules JSON, optional:

```bash
cd ICU
pip install jsonschema   # or use a venv
python3 tools/validate_rules_schema.py
```

The validator checks `rules/en.json`, `rules/zh.json`, `rules/ar.json`, `rules/bn.json`, and `rules/ru.json` against `docs/rule.schema.json`. If a new dedicated C++ `action` string is added, also extend the schema enum.

### Build Example

Paths depend on your ICU install, such as `brew install icu4c` on macOS or Conda.

```bash
cd ICU
g++ -std=c++17 -O2 en.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o en_tts

g++ -std=c++17 -O2 zh.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o zh_tts

g++ -std=c++17 -O2 ar.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o ar_tts

g++ -std=c++17 -O2 bn.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o bn_tts

g++ -std=c++17 -O2 ru.cpp tts_normalizer_engine.cpp \
  original/morphodita/build/_deps/morphodita-src/src_lib_only/morphodita.cpp \
  -I. -Ithird_party \
  -Ioriginal/morphodita/build/_deps/morphodita-src/src_lib_only \
  $(pkg-config --cflags --libs icu-icu) \
  -lpthread \
  -o ru_tts
```

`ru_tts` requires a MorphoDiTa model path at runtime:

```bash
./ru_tts --morph-model original/morphodita/models/russian-syntagrus-morphodita-only.tagger
```

Run from the `ICU` directory so `rules/*.json` resolve relative to the source paths.

### Debug Logging

Set `TTS_NORMALIZER_DEBUG` to any non-empty value to print one line to stderr for each regex hit, including `locale`, `rule_index`, `rule_id`, `action`, and the matched UTF-8 snippet.

```bash
export TTS_NORMALIZER_DEBUG=1
./zh_tts
```

### Parity Note

The literal tail in `generate_tts_rules_json.py` is a subset of the old monolithic `en.cpp` / `zh.cpp` implementation. Long-tail items such as Greek letters and full math symbol tables can be migrated incrementally by appending TSV rows. Rule order matters.

## 中文

本项目是一个面向 TTS 前端的多语言文本归一化原型。大多数 pattern、replacement、单位和货币表都放在 `rules/` 下的 **JSON** 中，因此产品侧调整规则时通常不需要改 C++。

**Phase B - pattern_defs：** 每个语言规则文件都可以包含顶层的 **`pattern_defs`**，用于定义命名 ICU 正则片段。**`rules[].pattern`** 可以通过 **`{{NAME}}`** 引用这些片段；`TtsNormalizerEngine::loadRules` 会先稳定解析这些定义之间的互相引用，再展开到最终规则中。该语法与 `tools/pattern_blocks.py` 中的生成器保持一致。普通 TSV literal 规则通常仍保留纯 pattern，不使用 placeholder。

### 目录结构

| 路径 | 作用 |
|------|------|
| `en.cpp` / `zh.cpp` / `ar.cpp` / `bn.cpp` / `ru.cpp` | 各语言的轻量 driver：使用 ICU `RuleBasedNumberFormat`，加载 JSON 规则并执行 pipeline |
| `tts_normalizer_engine.hpp` / `tts_normalizer_engine.cpp` | ICU regex 执行引擎；pipeline 规则基本都是 `action: "exec"` 加 JSON `steps`。当前只有拼音和 emoji 仍是专门的 C++ action |
| `rules/en.json` | 英文 pipeline 和 literal 规则 |
| `rules/zh.json` | 中文 pipeline 和 literal 规则 |
| `rules/ar.json` | 阿拉伯语 pipeline 和 literal 规则 |
| `rules/bn.json` | 孟加拉语 pipeline 和 literal 规则 |
| `rules/ru.json` | 俄语 pipeline 和 literal 规则，包含形态感知的数字处理 |
| `rules/zh_pinyin.json` | 带声调拼音到汉字的映射，供拼音规则使用 |
| `tools/generate_tts_rules_json.py` | 从结构化 Python 数据重新生成各语言 JSON 规则 |
| `docs/tts_ops.md` | 交接文档：列出所有 `exec` step 的 `op` 和专用 action |
| `docs/tts_locale_field_matrix.md` / `.csv` | 只作参考的多语言字段矩阵，由 `tools/export_locale_field_matrix.py` 生成 |
| `docs/rule.schema.json` | 所有 `rules/<locale>.json` 共用的 JSON Schema |
| `third_party/nlohmann/json.hpp` | 单头文件 JSON parser，MIT 许可证 |

### 如何编辑规则

1. **简单查找/替换：** 在 `tools/generate_tts_rules_json.py` 中添加 `EN_LITERALS_TSV` / `ZH_LITERALS_TSV` / `_AR_LITERAL_ROWS` / `_BN_LITERAL_ROWS` / `_RU_LITERAL_ROWS`，或扩展对应的 `*_pipeline_rules()`。
2. **单位 / 货币：** 修改同一个脚本中的 `*_unit_*()` 和 `*_currency_map()` 字典。
3. **新行为：** 优先在 `tools/generate_tts_rules_json.py` 中添加 `exec` steps，或者直接手动编辑 `rules/*.json`。只有当现有 primitive 无法表达新算法时，才在 `applyExecStep` 中新增 C++ `op`。

重新生成 JSON：

```bash
cd ICU
python3 tools/generate_tts_rules_json.py
```

校验规则 JSON，可选：

```bash
cd ICU
pip install jsonschema   # 也可以放在 venv 里
python3 tools/validate_rules_schema.py
```

该命令会用 `docs/rule.schema.json` 校验 `rules/en.json`、`rules/zh.json`、`rules/ar.json`、`rules/bn.json` 和 `rules/ru.json`。如果在 C++ 中新增了专用 `action` 字符串，也要同步扩展 schema 里的 `enum`。

### 构建示例

路径取决于本机 ICU 安装位置。macOS 可通过 `brew install icu4c` 安装，也可以使用 Conda 中的 ICU。构建命令见上方英文部分，俄语 `ru_tts` 运行时需要指定 MorphoDiTa 模型：

```bash
./ru_tts --morph-model original/morphodita/models/russian-syntagrus-morphodita-only.tagger
```

建议从 `ICU` 目录运行，这样 `rules/*.json` 能按源码中的相对路径正确解析。

### 匹配日志（调试）

设置 `TTS_NORMALIZER_DEBUG` 为任意非空值后，每次 regex 命中都会向 stderr 打一行日志，包括 `locale`、`rule_index`、`rule_id`、`action` 和 UTF-8 的 `matched` 片段。

```bash
export TTS_NORMALIZER_DEBUG=1
./zh_tts
```

### 兼容性说明

`generate_tts_rules_json.py` 末尾的 literal 规则目前只是旧版单体 `en.cpp` / `zh.cpp` 的一个子集，主要覆盖缩写、常见单位和 emoji。希腊字母、完整数学符号表以及其它长尾规则可以后续逐步迁移到 TSV。规则顺序很重要。
