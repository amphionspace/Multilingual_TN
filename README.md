# ICU TTS text normalization (config-driven)

Rules are **JSON** under `rules/` so product tweaks do not require editing C++ for most pattern/replacement and unit/currency tables.

**Phase B — pattern_defs:** each locale file may include a top-level **`pattern_defs`** map of named ICU fragments. **`rules[].pattern`** strings may embed **`{{NAME}}`** placeholders; `TtsNormalizerEngine::loadRules` resolves them after stabilizing mutual references among defs (same syntax as the generator in `tools/pattern_blocks.py`). Literal TSV rows usually keep plain patterns without placeholders.

## Layout

| Path | Role |
|------|------|
| `en.cpp` / `zh.cpp` / `ar.cpp` / `bn.cpp` / `ru.cpp` | Thin drivers: ICU `RuleBasedNumberFormat` + load JSON + run pipeline |
| `tts_normalizer_engine.hpp` / `tts_normalizer_engine.cpp` | ICU regex runner; pipeline actions are almost entirely `action: "exec"` with JSON `steps` (op dispatch). Only pinyin + emoji remain as dedicated C++ actions. |
| `rules/en.json` | English pipeline + literal rules |
| `rules/zh.json` | Chinese pipeline + literal rules |
| `rules/ar.json` | Arabic pipeline + literal rules |
| `rules/bn.json` | Bengali pipeline + literal rules |
| `rules/ru.json` | Russian pipeline + literal rules (+ morph-aware numerals) |
| `rules/zh_pinyin.json` | Tone-marked pinyin → 汉字 (used by pinyin rules) |
| `tools/generate_tts_rules_json.py` | Regenerates `en.json` / `zh.json` / `ar.json` / `bn.json` / `ru.json` from structured Python data |
| `docs/tts_ops.md` | Handoff: lists every `exec` step `op` plus dedicated actions; extend when adding locales or new ops |
| `docs/tts_locale_field_matrix.md` / `.csv` | Reference-only locale field matrix (not loaded at runtime); regenerated by `tools/export_locale_field_matrix.py` (also runs at end of `generate_tts_rules_json.py`) |
| `docs/rule.schema.json` | Single shared JSON Schema for all `rules/<locale>.json` documents (not loaded at runtime); validate with `tools/validate_rules_schema.py` after `pip install jsonschema` |
| `third_party/nlohmann/json.hpp` | Single-header JSON parser (MIT) |

## Editing rules

1. **Simple find/replace** — add rows to `EN_LITERALS_TSV` / `ZH_LITERALS_TSV` / `_AR_LITERAL_ROWS` / `_BN_LITERAL_ROWS` / `_RU_LITERAL_ROWS` in `tools/generate_tts_rules_json.py` (tab-separated or `(pattern, replace)` pairs) or extend the `*_pipeline_rules()` lists for new **actions**.
2. **Units / currency** — edit the `*_unit_*()` / `*_currency_map()` dicts in the same script.
3. **New behavior** — prefer adding `exec` steps in `tools/generate_tts_rules_json.py` (or hand-editing `rules/*.json`). Add C++ only for a **new `op`** inside `applyExecStep` when no existing primitive fits (e.g. new algorithmic feature).

Regenerate JSON:

```bash
cd ICU
python3 tools/generate_tts_rules_json.py
```

### Validate rules JSON (optional)

```bash
cd ICU
pip install jsonschema   # or use a venv
python3 tools/validate_rules_schema.py
```

Checks `rules/en.json`, `rules/zh.json`, `rules/ar.json`, `rules/bn.json`, and `rules/ru.json` against **`docs/rule.schema.json`**. When you add a new dedicated `action` string in C++, extend the `enum` in that schema file.

`zh_pinyin.json` is refreshed from the existing file when present; to rebuild from a legacy C++ map, place `zh_legacy_with_pinyin_map.cpp` next to this README (one-time).

## Build (example)

Paths depend on your ICU install (`brew install icu4c` on macOS, or Conda).

```bash
cd ICU
g++ -std=c++17 -O2 en.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o en_tts

g++ -std=c++17 -O2 zh.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o zh_tts

g++ -std=c++17 -O2 ar.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o ar_tts

g++ -std=c++17 -O2 bn.cpp tts_normalizer_engine.cpp \
  -I. -Ithird_party \
  $(pkg-config --cflags --libs icu-icu) \
  -o bn_tts

g++ -std=c++17 -O2 ru.cpp tts_normalizer_engine.cpp \
  original/morphodita/build/_deps/morphodita-src/src_lib_only/morphodita.cpp \
  -I. -Ithird_party \
  -Ioriginal/morphodita/build/_deps/morphodita-src/src_lib_only \
  $(pkg-config --cflags --libs icu-icu) \
  -lpthread \
  -o ru_tts
```

`ru_tts` requires MorphoDiTa model path at runtime:

```bash
./ru_tts --morph-model original/morphodita/models/russian-syntagrus-morphodita-only.tagger
```

Run from the `ICU` directory so `rules/*.json` resolve relative to the sources (`__FILE__`-based `rules/` path).

### Match logging (debug)

When **`TTS_NORMALIZER_DEBUG`** is set to any non-empty value, each regex hit prints one line to **stderr**, including **`locale`**, **`rule_index`** (0-based position in the loaded `rules` array), **`rule_id`** (from JSON **`id`**, regenerated by `tools/generate_tts_rules_json.py` as `en_00` / `zh_10` / `ar_05` / `bn_08` / `ru_03` … — numeric suffix equals `rule_index`), **`action`** (`exec`, `pinyin_*`, `emoji_clear`, or `(replace)`), and a UTF-8 **`matched`** snippet (truncated if long).

Example:

```bash
export TTS_NORMALIZER_DEBUG=1
./zh_tts
```

## Parity note

The literal tail in `generate_tts_rules_json.py` is a **subset** of the old monolithic `en.cpp` / `zh.cpp` (abbreviations + common units + emoji). Greek letters, full math symbol tables, and other long tails can be migrated incrementally by appending TSV lines—order matters (keep **loose number** rules before literals that still expect ASCII digits, matching the legacy pipeline).
