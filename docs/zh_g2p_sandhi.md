# 中文变调 G2P 模块（`data/zh_g2p`）

在**查完词典之后**对拼音序列做声调改写:三声变调、「一」「不」变调、结构性轻声、「啊」音变。
不查词典、不做汉字→拼音、不做多音字消歧——那些是上游 G2P 的职责。

```
文本 → TN(归一化) → G2P 查词典(汉字→带调拼音) → 【本模块:变调】 → 音素 → 声学模型
```

复用 TN 的同一套 `TtsNormalizerEngine`:规则写在 JSON 里顺序执行,只有"三声连读"和"声调符号
适配"两件事需要 C++ op(注册在 `chinese_g2p` backend 里)。引擎本体未做任何改动。

| 文件 | 作用 |
|---|---|
| `data/zh_g2p/config.json` | 资源目录入口,指定 backend 与规则文件 |
| `rules_v2/zh_g2p_sandhi.json` | 全部变调规则(有序); `metadata.pipeline_kind=g2p_sandhi` 表示**不继承 TN frontend bookends** |
| `unified/chinese_g2p_backend.cpp` | backend `chinese_g2p`,注册 `tone3_sandhi`、`py_tone_mark_to_digit` |
| `test/g2p/zh_sandhi_cases.tsv` | 分桶金标用例 |
| `test/scripts/run_g2p_tests.sh` | 回归脚本 |

## Token 契约

一行一句,token 之间**单个空格**分隔:

```
我很想买一本书  →  wo3 | hen3 xiang3 | mai3 | yi1 | ben3 shu1
```

- **音节** = 拼音字母 + 声调数字 `1-5`,其中 **`5` = 轻声**(输入写 `0` 也接受,入口会归一化成 `5`)。
- **`|`** = 词/韵律词边界,由上游分词给出。**三声变调的分组正确性依赖它**(见下)。
- **标点**原样透传,并天然打断连读。
- 输出格式与输入一致(**保留 `|`**,无损);下游若不需要边界,删掉 `|` token 即可。

**与 TN 的边界:** `zh_g2p` / `en-zh-g2p` 在变调阶段**不再**跑 TN 的 frontend bookends
(如 `replace_vertical_line_punct`)。规则文件通过 `metadata.pipeline_kind=g2p_sandhi` 声明这一点,
避免把分词词界 `|` 误当成原文竖线分隔符而插入逗号。

入口另有适配:带调符号的拼音(`nǐ hǎo`)会先转成数字调(`ni3 hao3`),未标调的音节按轻声处理
(`de` → `de5`),因此上游用哪种写法都能接。

## 处理顺序

顺序不能随意调换,规则之间有依赖:

| 趟 | 内容 | 说明 |
|---|---|---|
| ① 入口归一化 | 边界空格规整、空白折叠、`0`→`5`、声调符号→数字 | |
| ② 结构性轻声 | X不Y、A一A、儿化 | 必须在 ③④ 之前,否则「一/不」会先被变调 |
| ③ 「一」变调 | 一+④→`yi2`;一+①②③→`yi4` | 读的是**后字的原始声调**,故在三声变调之前 |
| ④ 「不」变调 | 不+④→`bu2` | 同上 |
| ⑤ 三声变调 | 连续三声整段改写 | 在最后,基于前面几趟定下的声调 |
| ⑥ 语气词 | 先「啊」音变(`a5`→`ya5`/`wa5`/`na5`),再按后接标点定调 | 音变看前字韵尾,定调看后接标点,两者叠加 |
| ⑦ 出口清理 | 空格折叠、去首尾空格 | |

**② 结构性轻声**的三条:
- **X不Y**:任何**三音节词**中间是「不」就读轻声——`dui4 bu4 qi3`(对不起)、`cha4 bu4 duo1`(差不多)、
  `kan4 bu4 jian4`(看不见)、`hao3 bu4 hao3`(好不好)。
- **A一A**:`kan4 yi1 kan4`(看一看)→ `yi5`,要求前后音节相同且整词恰好三音节。
- **儿化**:多音节词词尾的 `er2` 读轻声(`hua1 er2`→`hua1 er5`),
  例外词 女儿/老儿/男儿/少儿/小儿 保持原调。

**⑥ 语气词**分两层,是两种不同现象,会叠加:
- **音变**(看前字韵尾):`hao3 a5` → `hao3 wa5`
- **定调**(看后接标点):`a5 ?` → `a2`、`a5 !` → `a4`、`en5 ?` → `en2`,`en5` 默认读 `en4`
- 叠加示例:`hao3 a5 ?` → `hao3 wa2 ?`

## 三声变调的分组算法

连续三声怎么变,取决于**韵律分组**,这正是需要 `|` 的原因。算法分两步:

1. **词内**是左分支:一个词里除最后一个三声外,**全部**降为二声。
   `zhan3 lan3 guan3`(展览馆)→ `zhan2 lan2 guan3`
2. **跨词**是右分支:从右往左扫,只有"后面仍然是三声"的音节才降调。
   于是前一个音节遇到已经变成二声的邻居时,自己保持三声。
   `wo3 | hen3 | hao3`(我很好)→ `wo3 hen2 hao3`,**不是** `wo2 hen2 hao3`
   `xiao3 | lao3 hu3`(小老虎)→ `xiao3 lao2 hu3`

两步合起来能同时给出教科书里的两种读法:
`展览馆` = 2 2 3(词内左分支),`小老虎` = 3 2 3(跨词右分支)。

**轻声是阻断符**:三声后面跟轻声时不触发连读(`wo3 de5` 保持不变)。这是有意的简化——
严格说要看轻声音节的底层调,收益低且依赖词典标注。

## 职责划分:本模块 vs 词典

| 归谁 | 内容 |
|---|---|
| **本模块(规则)** | 三声变调;「一」「不」变调;结构性轻声(X不Y、A一A);儿化;「啊」音变与语气词定调 |
| **上游词典** | 词汇性轻声(的/了/着/子/头/们…);多音字消歧;基础字词读音 |

### 「一」「不」的守卫

「不」的守卫是**词内非首音节的 `bu4` 不参与变调**。这样 `gan4 bu4`(干部,与"不"同音)不会被误改。
上游分词把单独的「不」并到**后一个词**,所以「不」在词内总是首音节,这条守卫是安全的。

「一」不能用同一条守卫——`bu4 yi1 ding4`(不一定)里的「一」是词中音节,必须变调。
因此「一」的守卫拆成三层:

| 守卫 | 挡住的情况 | 仍然放行 |
|---|---|---|
| `(?<!di4 )` | 序数前缀 `di4 yi1 tian1`(第一天) | — |
| 词**末**「一」 | `tong3 yi1 \| le5`(统一)、`wan4 yi1`(万一) | `bu4 yi1 ding4`(不一定,词中) |
| 后接词表 | `yi1 yue4/ri4/hao4`(一月/一日/一号)、`yi1 dui4 yi1`(一对一) | `yi1 dui4`(一对,照常变调) |

## 与 frontend_rules 参考实现的交叉验证

同事的 `frontend_rules/ops/sandhi.py` + `rules/g2p_sandhi/zh.json` 是同一套变调的 Python 参考实现。
本模块的规则逐条对照过,`test/g2p/zh_sandhi_cases.tsv` 里的用例大部分直接来自该实现。两处需要注意:

**`|` 的语义两边不同。** 参考实现把 `|` 放进 `sandhi_pause_tokens_extra`,当作**停顿符,直接打断连读**;
本模块把 `|` 当作**韵律词边界,跨词仍变调**,只是分组方式改为右分支。所以 `wo3 | hen3 | hao3`
在参考实现里完全不变调,在这里是 `wo3 | hen2 | hao3`。参考实现的主路径是"按词逐个处理 + 一趟不带
边界的扁平 token 兜底",实际不冲突;但**接上游前必须把 `|` 的语义定死**。不带 `|` 的扁平输入下,
两套实现结果完全一致。

**三条例外词故意没有对齐。** 参考实现用汉字词表挡住 不字 / 一是 / 一加;这些词表键在拼音层面是
有歧义的,照搬会误伤更常见的 不自(量力) `bu2 zi4`、一世/一事/一时 `yi2 shi4`、一家 `yi4 jia1`。
这里保留常规变调,用例记在 `divergence` 桶里。

## 用法

```bash
bash test/scripts/build_unified.sh                 # 需要 ICU_ROOT,同 TN
echo 'wo3 | hen3 xiang3 | mai3 | yi1 | ben3 shu1' \
  | ./test/bin/tts_cli --data data/zh_g2p
# -> wo3 | hen2 xiang2 | mai3 | yi4 | ben3 shu1
```

调试单条规则命中情况,与 TN 一样用 `TTS_NORMALIZER_DEBUG=1`。

## 测试

```bash
bash test/scripts/run_g2p_tests.sh
```

用例按规则分桶(`tone3_word` / `tone3_cross` / `tone3_block` / `yi` / `yi_keep` / `bu` /
`bu_neutral` / `neutral` / `erhua` / `a_particle` / `interjection` / `entry` / `divergence`),
整批一次跑完再逐行比对。**每条规则都必须有用例**:引擎在正则编译失败时是静默跳过的(原文返回),
只有金标用例能把这种"哑火"抓出来。

## 已知取舍

- **三个以上连续三声的分组本身有韵律歧义**,算法给的是词边界驱动的确定解;需要精细控制时,
  应由上游把词/韵律词边界切准,而不是在这里加特例。
- **上游不给 `|` 时**退化为"整串按右分支处理",双音节仍然正确,多音节可能偏离预期。
- **`-ng` 韵尾与 zhi/chi/shi/ri、zi/ci/si 后的「啊」音变未改写**(`nga`/`ra`/`za` 不是合法拼音
  音节,写出来下游音素表未必接得住),保持原样更安全。
- **语气词定调按拼音判断**(`a5`/`en5`),参考实现是按汉字判断的。中性调的 `a5`/`en5` 基本只可能是
  「啊」「嗯」,误判风险低,但不为零。
- **不字 / 一是 / 一加三条汉字词表例外未实现**,原因见上一节。
